# Working style

How we work on Conduit and what the code should look like. CLAUDE.md sends
agents here. Read how-i-like-to-work.md before any work, then the style file
for the area you're touching.

| File | Covers |
|---|---|
| how-i-like-to-work.md | collaboration: git, planning, asking, verification, communication, wrap-ups |
| go.md | `server/` code |
| web.md | `web/` code |
| design.md | how `web/` looks, reads and moves: when to design, what to ask first, showing options, the accessibility floor |
| repo.md | layout, just, pinned versions, CI, config, docs |
| sources.md | where each rule came from and how it held up against outside sources |

Nothing here is beyond question: not chat, not these docs, not my habits.
When best practice disagrees with any of them, say so with a source before
acting. I decide, and the decision holds until it's changed.

To change a rule, edit the doc in the same change that needed it, and add
the reason to sources.md. Rules come from real corrections, not speculation.
